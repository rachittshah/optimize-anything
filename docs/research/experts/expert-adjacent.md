# Adjacent-fields scout: ideas from outside prompt optimization

Scope: ideas from compilers/autotuning, AutoML/HPO, game AI, operations research (OR), program synthesis and fuzzing, mapped onto the `optimize-anything` loop.
Date: 2026-11-11. Code hooks I read: `core/engine.py:106-190` (run loop: select at :123, parent minibatch eval at :136, propose at :153, child eval at :166), `strategies/selection.py` (Selector protocol), `strategies/sampling.py` (EpochBatchSampler), `proposer/prompts.py`, `core/pareto.py`.
Evidence labels: **strong** = shown on LLM text or program optimization in a primary paper; **medium** = strong in the home field plus some LLM-side signal; **weak** = home-field only, the transfer is my argument.
"verified" = I opened a search hit for the primary source this session. "unverified" = cited from memory, URL not checked this session.

## Loop steps (used in the "Transfer" column)
S1 select parent → S2 minibatch eval (3 ex) → S3 reflect + rewrite one component → S4 accept if minibatch sum improves → S5 full valset eval → S6 frontier update. Also X = across-run state.

## Metric key
M = valset Δ / sample efficiency (score per eval) / $ cost / train-val gap / effort (1 easy – 5 hard) / evidence. Arrows are expected direction: ↑ up, ↓ down, ≈ no change, ? unclear.

## Top 5 for THIS codebase (ranked by expected gain ÷ effort)

Shared A/B protocol for all five: 3 tasks (regex, date parser, ticket router), each with 24 train / 18 val / 18 test. **5 seeds × 2 arms × 3 tasks = 30 runs per experiment**, same proposer model, temperature 0, **fixed evaluator-call budget** (e.g. 150 evals/run; count *every* example scored, including screens and races). Report: test score at budget (primary), area under the best-val-vs-evals curve (efficiency), $ (proposer + judge tokens), val−test gap. Pair by seed (same seed → same minibatch order); paired Wilcoxon across 15 task-seed pairs, plus per-task means. Deterministic tasks make evaluator noise zero, so all variance comes from the proposer and minibatch sampling.

### 1. Feasibility gate + behavioural dedupe (rows 6, 15). Effort 1
- `evaluators/*`: optional `feasible: bool` and `outputs: list` on the result. Python/shell evaluators already produce outputs, so expose them.
- `engine.run` after :153 (before the child eval at :166): if a static check fails (`re.compile`, JSON schema, router label set), reject, log the reason into the next ASI, and spend 0 evals. After :166: `sig = hash(tuple(outputs))`; if the signature is already in `state.seen_sigs`, skip val eval (S5).
- Test: arm A baseline, arm B gate+dedupe. Expect efficiency ↑ and an identical or better test score; fastest win, and it lowers costs for every later experiment.

### 2. Counterexample mining from a dev split (rows 1, 16). Effort 2
- Split discipline: train 24 → *train 16 + dev 8*. Val/test stay untouched, so the val gap stays honest.
- New `strategies/sampling.py: HardPoolSampler(minibatch_size=3, hard_frac=1/3)`. Every K=3 iterations, eval the current best on dev; failing dev examples move into the hard pool and train. For regex/date only: every 10 iterations, ask the LLM for 5 tricky inputs; the *reference oracle* labels them (the benchmark has deterministic ground truth), and only examples that disagree with the candidate are kept.
- Test: arm A EpochBatchSampler on all 24 train vs arm B HardPool (16 + mined). Hypothesis: test score ↑ on regex/date, ≈ on the router. Watch: the val−test gap must not grow.

### 3. Operator portfolio with sliding-window UCB + tabu memory (rows 2, 7, 8). Effort 2
- `proposer/prompts.py`: 4 templates = `rewrite` (current), `section_edit` (LNS: pick the section with the most attributed failures), `merge` (two frontier parents, GEPA-style), `compress` (shorten without changing behaviour).
- `strategies/operators.py: UCBOperatorBandit(window=20, c=0.5)`; reward = max(0, Δ minibatch) for accepted children, 0 otherwise. Tabu: the last 5 rejected diff summaries per component go into the prompt as "already tried, didn't help"; children are deduped by normalized-text hash.
- Test: arm A `rewrite` only vs arm B bandit. Also log arm-pull counts per task; that shows which operator wins on multi-component routing vs one-shot regex.

### 4. Racing acceptance with SPRT stopping (rows 4, SPRT). Effort 2
- Replace the S4 rule at `engine.py` ~:170. Evaluate parent and child on the same sequence of train examples (3 → up to 9). After each example, update the paired win/loss record; reject at once on 2 straight losses with no wins, accept when the SPRT bound or a sign-test p<0.2 is crossed, cap at 9. The eval cache means the parent's scores cost nothing again.
- Shares code with the planned statistical promotion, which needs the same paired test.
- Test: arm A "sum improves on 3" vs arm B race. Expect fewer false accepts (lower val−test gap) at similar evals, because losses stop at 1–2 examples.

### 5. Pairwise TrueSkill rating for LLM-judge evaluators (row 13). Effort 3
- Applies only when the evaluator is an LLM judge. The 3 deterministic tasks don't exercise it, so **add a 4th judge-scored variant**: the ticket router's *reply text* graded by an LLM rubric.
- `evaluators/llm_judge.py: pairwise(a_out, b_out, example)` runs both orderings; a tie = disagreement between the two orderings. Keep `mu, sigma` per candidate (a ~40-line Bradley-Terry/TrueSkill update; no dependency needed). Accept the child if P(child > parent) > 0.75; select parents by an upper confidence bound μ+σ, which fixes the Elo newcomer problem DEEVO reported.
- Test: arm A absolute 0–1 judge vs arm B pairwise. Ground truth = a held-out *deterministic* proxy (required fields present, correct routing label) plus 20 human spot labels. Hypothesis: lower judge-score inflation (gap ↓), at ~1.3–2× judge tokens.

### Runners-up (not in top 5)
- **Surrogate pre-screen of k children (row 5)**: promising, but it doubles proposer tokens; try after #1, using its cheap 1-example screen.
- **Library learning across runs (row 14)**: highest long-run upside, but our benchmark is a single run per task. Testing it needs a *task-family* split (e.g. learn on date-parser v1, apply to v2).
- **UCT / Go-Explore selection (11, 12)**: evidence for them is against weak baselines; GEPA's per-example Pareto front is already a behaviour archive. Low expected gain.
- **Simulated annealing (9)**, **PBT islands (10)**: SA overlaps with Pareto diversity; PBT needs parallel runs, so it comes later, once the cross-agent tooling lands.
